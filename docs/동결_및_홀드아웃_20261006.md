# 동결 기준과 홀드아웃 평가 절차 (2026-10-06)

홀드아웃 점수는 **동결한 시스템을 처음 보는 질문으로 한 번만** 잰 점수입니다. 이 문서는 무엇을 동결했는지, 개발용 평가셋에서 어디까지 확인했는지, 홀드아웃을 어떻게 돌리고 채점하는지를 적습니다.

## 1. 동결한 것

지문(SHA256 앞 12자리)은 `eval/freeze.json`에 있고, `python freeze_check.py`가 지금 상태와 비교합니다.

| 구분 | 동결 값 |
| --- | --- |
| 답변 모델 | gpt-4o-mini, 온도 0 (빈손도 같은 모델·온도) |
| 임베딩 | text-embedding-3-small |
| 데이터 | 문서 104개 수집 / 93개 사용, OCR 48쪽 포함, 약 283만 자 (`data/manifest.csv`) |
| 청킹·인덱스 | fixed (쪽 안에서 500자, 100자 겹침), 9,774조각 |
| 검색 | 상위 10, 한 문서 최대 2, 공공 자료 5개 이상(공공 몫은 한 문서 최대 1), 영어 번역 검색, 질문 끝 공통 요청("지도할 때 주의해야 할 점은?") 제거 |
| 범위 판정 | LLM 판정 + 범위 단어 규칙 + 범위 밖 질환(신장·관절염·디스크 등) 감지 + 생애 단계(폐경·임신 등)는 질환 아님 |
| 답변 규칙 | 결론 문단 → 지도할 때 유의할 점 → 회원에게서 지켜볼 점 → 근거, 근거 번호 필수, [OCR] 숫자 주의, 출처별 수치 차이 표시 |
| 가드 | 진단 요청이면 판정 금지 규칙 + 재작성 + 남으면 문장 삭제, 약·인슐린 조절 권유는 판정기 확인 + 재작성 + 남으면 삭제, 회원 조건이 없는 질문은 되묻기 |

동결 뒤에는 코드·프롬프트·데이터·인덱스를 바꾸지 않습니다. 바꿔야 하면 홀드아웃 점수는 버리고 새 홀드아웃 문항으로 다시 잽니다.

## 2. 개발용 평가셋에서 확인한 결과 (`eval/questions.csv`, 35문항)

질문은 "…하겠대요. 지도할 때 주의해야 할 점은?" 꼴입니다(2026-10-06에 "어떻게 생각해?"에서 바꿈). 35문항 = 범위 안 30 + 범위 확인 5.

| 측정 | 기준 | 빈손 (`blank_…_1643`) | RAG 동결 (`rag_…_1645`) |
| --- | --- | --- | --- |
| 기대 근거 문서 검색 적중 | 30 | - | 29 (97%) |
| 위반이 있는 문항 | 35 | 9 (26%) | 0 |
| └ 범위 밖 질환 조언 | 6 | 6 (24, 31~35번) | 0 |
| └ 진단 표현 | 1 | 1 (30번) | 0 |
| └ 약·인슐린 조절 권유 | 35 | 2 (1, 18번) | 0 |
| 범위 밖 거절 / 범위 일부 처리 | 3 / 2 | 0 / 0 | 3 / 2 |
| 범위 판정이 맞음 | 35 | - | 35 |
| 확인 가능한 출처 | 답변 수 | 0 / 35 | 32 / 32 |
| 되묻기 (조건 누락) | 2 | 0 | 2 |
| 기대 근거 문서를 인용 | 30 | - | 22 |
| 판단 정확도 · 세부 충족률 | 35 · 154 | 사람 채점 | 사람 채점 |

- 위반은 범위 밖 조언만 문항을 읽어 셌고, 나머지는 `eval_answers.py`가 셉니다.
- 동결 직전에 고친 것: 질문 끝 공통 요청 제거(바꾼 문장 때문에 검색 적중 27 → 24로 떨어졌던 것을 회복), 공공 몫 문서당 1(OCR한 지침서 조각이 다른 공공 자료를 밀어내던 것), 출처별 수치 차이 표시 규칙. 위험·기전 이름을 넣은 번역 확장은 시험했지만 적중이 줄어(27 → 26) 쓰지 않습니다.
- 남은 약점: 12번(운동과 식욕 조절 논문) 검색 실패, 답변이 인용한 원문에 없는 수치를 쓰는 경우(채점지의 인용 원문 칸에서 확인).

## 3. 홀드아웃 문항 만들기

- `eval/holdout_template.csv`를 복사해 `eval/holdout.csv`로 씁니다. 칸은 개발용 평가셋과 같습니다.
  - `채점포인트`: 첫 포인트는 `판단: …`(결론 하나), 나머지 세부 포인트는 판단과 겹치지 않게, ` / `로 구분
  - `기대범위`: 비워 두면 유형으로 정함(범위 밖 → out, 범위 일부 → partial, 나머지 → in). 둘 다 인정하면 `in,partial`
  - `근거위치`: 기대 근거 문서 ID(검색 평가용). 범위 확인 문항은 비움
- 시스템 답변을 보기 전에 질문과 채점 포인트를 모두 확정합니다. 답변을 보고 채점 포인트를 고치면 홀드아웃이 아닙니다.
- 개발용 35문항과 같은 상황을 문장만 바꿔 넣지 않습니다. 유형 비율(계획 판단·운동 시 문제·기전·조건 누락·경계·범위 확인)은 개발용과 비슷하게 맞추면 비교하기 좋습니다.

## 4. 홀드아웃 돌리기와 채점

```bash
python freeze_check.py                                            # "동결 상태 그대로입니다."가 나와야 함
python blank_test.py --questions eval/holdout.csv                 # 빈손
python rag_test.py --questions eval/holdout.csv                   # RAG (동결 설정이 기본값)
python eval_retrieval.py --questions eval/holdout.csv --only fixed --k 10 --per-doc 2 --public 5 --public-per-doc 1 --translate
python eval_answers.py --questions eval/holdout.csv eval/results/blank_gpt-4o-mini_holdout_<날짜>.csv eval/results/rag_gpt-4o-mini_fixed_holdout_<날짜>.csv
python make_grading.py eval/results/blank_gpt-4o-mini_holdout_<날짜>.csv --questions eval/holdout.csv
python make_grading.py eval/results/rag_gpt-4o-mini_fixed_holdout_<날짜>.csv --questions eval/holdout.csv
# 채점지 [ ] 칸을 O / △ / X로 채운 뒤
python score_grading.py eval/results/*holdout*_채점지.txt
```

- 홀드아웃은 한 번 돌린 결과로 점수를 냅니다(온도 0이어도 실행마다 조금 달라지므로 다시 돌려 좋은 쪽을 고르지 않음).
- 보고할 점수: 판단 정확도, 세부 충족률(O=1, △=0.5), 위반이 있는 문항 비율, 인용 원문 일치율, 검색 적중률. 빈손과 RAG를 나란히 적습니다.
