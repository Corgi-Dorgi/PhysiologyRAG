# 동결 기준과 홀드아웃 평가 절차 (2026-10-06)

홀드아웃 점수는 **동결한 시스템을 처음 보는 질문으로 한 번만** 잰 점수입니다. 이 문서는 무엇을 동결했는지, 개발용 평가셋에서 어디까지 확인했는지, 홀드아웃을 어떻게 돌리고 채점하는지를 적습니다.

## 0. 동결 시점

- **동결 커밋: `b179963` (태그 `freeze-20261007`), 2026-10-07**
- 이 커밋 이후 검색·프롬프트·규칙·데이터·인덱스를 고치지 않습니다. 이후 커밋은 채점 결과·문서·홀드아웃 문항만 더합니다.
- 홀드아웃을 돌리기 전 `python freeze_check.py`가 "동결 상태 그대로입니다."를 내야 합니다.

## 3. 홀드아웃 문항 만들기

- `eval/holdout_template.csv`를 복사해 `eval/holdout.csv`로 씁니다. 칸은 개발용 평가셋과 같습니다.
  - `채점포인트`: 첫 포인트는 `판단: …`(결론 하나), 나머지 세부 포인트는 판단과 겹치지 않게, ` / `로 구분
  - `기대범위`: 비워 두면 유형으로 정함(범위 밖 → out, 범위 일부 → partial, 나머지 → in). 둘 다 인정하면 `in,partial`
  - `근거위치`: 기대 근거 문서 ID(검색 평가용). 범위 확인 문항은 비움
- 시스템 답변을 보기 전에 질문과 채점 포인트를 모두 확정합니다. 답변을 보고 채점 포인트를 고치면 홀드아웃이 아닙니다.
- 개발용 35문항과 같은 상황을 문장만 바꿔 넣지 않습니다. 유형 비율(계획 판단·운동 시 문제·기전·조건 누락·경계·범위 확인)은 개발용과 비슷하게 맞추면 비교하기 좋습니다.

## 4. 홀드아웃 돌리기와 채점

```bash
python freeze_check.py                                            # "동결 상태 그대로입니다."가 나와야 함
python blank_test.py --questions eval/holdout.csv                 # 빈손
python rag_test.py --questions eval/holdout.csv                   # RAG (동결 설정이 기본값)
python eval_retrieval.py --questions eval/holdout.csv --only fixed --k 10 --per-doc 2 --public 5 --public-per-doc 1 --translate
python eval_answers.py --questions eval/holdout.csv eval/results/blank_gpt-4o-mini_holdout_<날짜>.csv eval/results/rag_gpt-4o-mini_fixed_holdout_<날짜>.csv
python make_grading.py eval/results/blank_gpt-4o-mini_holdout_<날짜>.csv --questions eval/holdout.csv
python make_grading.py eval/results/rag_gpt-4o-mini_fixed_holdout_<날짜>.csv --questions eval/holdout.csv
# 채점지 [ ] 칸을 O / △ / X로 채운 뒤
python score_grading.py eval/results/*holdout*_채점지.txt
```

- 홀드아웃은 한 번 돌린 결과로 점수를 냅니다(온도 0이어도 실행마다 조금 달라지므로 다시 돌려 좋은 쪽을 고르지 않음).
- 보고할 점수: 판단 정확도, 세부 충족률(O=1, △=0.5), 위반이 있는 문항 비율, 인용 원문 일치율, 검색 적중률. 빈손과 RAG를 나란히 적습니다.
