# 만성질환 회원 운동지도 보조 AI (가칭)

당뇨·비만·고혈압이 있는 사람의 운동을 지도하는 트레이너를 위한 RAG 기반 QA 도구입니다. 연령·성별·질환 유형별로 운동 방법을 물으면 **주의사항**과 **질환 때문에 운동 중 항상성이 깨질 때 생기는 문제(혈당·혈압·체온·자율신경)**를 논문·학술지를 근거로 설명하고, 근거 문서와 쪽(또는 섹션)을 함께 보여줍니다. 진단·약 조절처럼 의료행위에 해당하는 질문은 의료기관으로 안내합니다.

모델을 다시 학습시키지 않고, 질문마다 모아 둔 문서에서 관련 부분을 찾아 그 근거로만 답하게 합니다(RAG).

이 프로젝트의 목표는 챗봇 자체가 아니라 **만들고 → 틀린 것을 찾고 → 고쳐서 → 수치로 증명하는 과정**입니다.

> 이 도구는 운동지도 보조용이며 의료 조언을 제공하지 않습니다.

## 해결하려는 문제

- 트레이너는 기본 기준은 알지만, 여러 질환이 겹친 회원이나 약을 먹는 회원 앞에서 어느 문서의 어느 기준을 적용할지 확인하기 어렵습니다.
- 회원은 "아침 안 먹고 왔어요", "혈압약 먹었어요"처럼 말하는데, 지침은 수치와 조건으로 적혀 있습니다.
- 범용 챗봇은 근거 위치를 주지 않고, 진단·약물 이야기까지 해서 비의료기관이 그대로 쓰기 어렵습니다.

## 범위

- **질환:** 당뇨(1형·2형·임신당뇨), 비만, 고혈압(원발성·이차성·임신 고혈압)
- **대상:** 연령별(성인·노인·청소년), 성별(남성·여성, 폐경 포함), 임신
- **답변 구성:** 대상 확인 → 권장 운동 → 주의사항 → 항상성이 깨질 때 생기는 문제(무엇이 → 어떤 기전으로 → 어떤 증상·위험) → 근거
- **근거 우선순위:** 학술(논문·학회지)을 먼저, 공공(보건복지부·질병관리청 등) 자료는 한국 기준 수치 보충
- **사용자:** 헬스장·PT 트레이너, 생활체육지도자
- **하지 않는 것:** 진단, 약 조절 조언, 질환 범위 밖 질문

## 평가

평가셋은 30문항(정답형 20 + 문서에 없는 질문 5 + 함정 5)이며, 문항마다 채점 포인트와 근거 문서·쪽 번호를 붙입니다. 현재 13문항 작성 완료(`eval/questions.csv`).
`근거위치` 칸에는 자동 채점용으로 `문서ID:인쇄쪽`을 적습니다 (예: `khepi-ob-001:105-106; khepi-pa-004:49`). 쪽은 PDF 순서가 아니라 원문에 인쇄된 쪽 번호입니다.

| 지표 | 뜻 |
| --- | --- |
| 검색 적중률 | 정답 근거가 검색 상위 5개 안에 드는 비율 |
| 채점 포인트 충족률 | 답에 꼭 들어가야 할 내용 중 들어간 비율 |
| 근거 표시 정확도 | 인용한 문서·쪽이 실제 내용과 일치하는 비율 |
| 조건 확인 | 빠진 조건(식사·약·컨디션 등)을 되묻는 비율 |
| 경계 준수 | 진단·약 조절 질문을 의료기관으로 안내한 비율 |

## 파싱·청킹과 검색 기준선

`chunk.py`가 사용 문서 41개를 정제해 세 가지 방식으로 자르고, `index.py`가 OpenAI `text-embedding-3-small`로 임베딩합니다. 청크가 수천 개 규모라 벡터 DB 없이 numpy로 전체 코사인 유사도를 계산합니다.

- 정제: 쪽마다 반복되는 머리말·꼬리말 제거, PDF 줄바꿈 복원(한글 단어 중간 끊김은 붙이고 표 칸은 띄움), 인쇄 쪽 번호 자동 인식(PDF 순서와 다른 문서가 있음: 2025 신체활동 안내서 20번째 쪽 = 16쪽), PMC 논문의 부속 섹션과 범위 밖 장(약물치료·입원 등) 제외
- 청크마다 실제로 텍스트가 들어간 쪽 목록을 기록해서, 빈 쪽을 건너뛴 청크가 그 쪽의 정답으로 잡히지 않게 합니다

| 전략 | 방식 | 청크 수 | 평균 글자 |
| --- | --- | --- | --- |
| fixed | 쪽 안에서 500자씩, 100자 겹침 | 6,301 | 403 |
| fixed_ctx | fixed + 청크 앞에 `[문서명 \| 쪽]` 머리말 | 6,301 | 499 |
| section_ctx | 제목·문단 경계로 나눠 900자까지 묶기 + 머리말 | 3,705 | 665 |

검색 평가 (`eval_retrieval.py`, 근거위치가 있는 11문항, 상위 5개):

| 전략 | 문서 41개 (2026-09-30) | 문서 62개, 질병관리청 추가 (2026-10-01) |
| --- | --- | --- |
| fixed | 0 (0%) | 0 (0%) |
| fixed_ctx | 2 (18%) | 2 (18%) |
| section_ctx | **4 (36%)** | **3 (27%)** |

- 질병관리청 문서를 더한 뒤 section_ctx에서 9번(비만 회원 유산소 강도)을 놓쳤습니다. '당뇨환자의 운동요법'의 같은 섹션 청크 3개가 상위 5개를 차지해서, 당뇨 환자 기준(최대심박수 50~70%)이 비만 질문에 끌려왔습니다 → 오답노트 후보(같은 문서·섹션 청크가 상위를 독점, 대상 질환 불일치).
- 3번(임신성 당뇨)은 질병관리청 '임신당뇨병 › 비약물 치료'가 2위로 검색됩니다. 근거위치를 이 문서로 고치면 적중으로 집계됩니다.

- 문서명 머리말과 구조 기반 청킹이 모두 효과가 있어서 이후 실험은 `section_ctx`를 기준선으로 씁니다.
- 문서를 늘리면 적중률이 오르기만 하지 않습니다. 비교할 때는 같은 문서 집합에서 측정해야 합니다.
- 3문항(5·6·7번)은 정답인 신체활동 지침서 47·49쪽의 텍스트가 추출되지 않아 검색으로는 맞힐 수 없습니다. 지침서는 홀수 쪽이 모두 0자입니다 → 첫 개선 실험(OCR)의 대상입니다.
- 오답노트 후보: 같은 안내서의 연도판(2024·2025·2026)이 상위 5개를 나눠 차지함, "40대 여성" 질문에 임신부 자료가 검색됨, 오래된 2005년 논문이 근거로 쓰임.
- RAG 답변 1차 결과: `eval/results/rag_gpt-4o-mini_section_ctx_20260930_1246.csv` (빈손 테스트와 같은 모델·온도, 채점 전)

### 목표 재정리 후 검색 개선 (2026-10-01)

질문은 한국어인데 학술 근거는 대부분 영어라서, 한국어 질문으로는 한국어 공공 자료만 올라오고 운동 생리 논문은 거의 검색되지 않았습니다. 청크에 꼬리표(학술/공공, 질환, 대상)를 붙이고 검색 방식을 바꿨습니다.

- **영어 번역 검색:** 질문을 영어로 번역(gpt-4o-mini)해 함께 검색하고, 두 점수 중 높은 쪽을 씁니다.
- **공공 자료 최소 개수:** 번역 검색만 쓰면 영어 논문만 올라와서 한국 기준 수치가 빠집니다. 상위 10개 중 5개 이상은 한국어 질문 점수로 고른 공공 자료로 채웁니다.
- **한 문서당 최대 2개:** 같은 문서·섹션의 비슷한 청크가 상위를 독점하지 않게 합니다.

| 검색 설정 (section_ctx) | 기존 11문항: 정답 쪽 적중 | 새 초안 26문항: 기대 문서 적중 | 상위 결과 중 학술 수 (새 문항) |
| --- | --- | --- | --- |
| 한국어 질문만, 상위 8 | 4 (36%) | 5 (19%) | 1.7 / 8 |
| + 한 문서당 2개 | 4 (36%) | 7 (27%) | 1.9 / 8 |
| + 영어 번역 검색 | 0 (0%) | 25 (96%) | 7.5 / 8 |
| + 번역 + 공공 5개 이상, 상위 10 (**현재 기본값**) | 4 (36%) | 25 (96%) | 5.0 / 10 |

- 새 초안 문항(`eval/questions_v2_draft.csv`)의 '기대 문서'는 논문을 고른 사람이 직접 단 문서 단위 정답이라 유리하게 나올 수 있습니다. 쪽·섹션 단위 정답과 채점 포인트는 사람 검토 후 확정합니다.
- 오답노트 후보: 고중량 운동 질문(17번)에서 발살바 압력 논문을 못 찾음, 운동 후 어지럼 질문(18번)에서 운동 후 저혈압 기전 논문을 못 찾음, 기전 질문에도 답변 형식 때문에 권장 운동 칸이 채워짐.

## 테스트 화면 (Streamlit)

`streamlit run app.py`를 실행하면 브라우저에서 답변을 확인할 수 있습니다.

- 질문을 직접 쓰거나 평가셋 문항을 고릅니다. 문항을 고르면 채점 포인트와 기대 근거 문서가 함께 보입니다.
- 왼쪽에 답변, 오른쪽에 검색된 근거(학술/공공, 점수, 인용 여부, 기대 문서 여부)가 나옵니다.
- 자동 점검: 형식 5칸(대상 확인·권장 운동·주의사항·항상성·근거)이 있는지, 인용 번호가 실제 검색 결과에 있는지, 학술 근거를 몇 개 인용했는지, 기대 문서가 검색됐는지.
- 사람 평가: 항목별 좋음/부족/틀림과 메모를 저장하면 `logs/qa_log.sqlite`에 쌓이고, 화면 아래에서 CSV로 받을 수 있습니다.
- 사이드바에서 청킹 방식, 근거 수, 공공 자료 최소 개수, 문서당 최대 개수, 영어 번역 검색을 바꿔 가며 비교할 수 있습니다.

## 실행 방법

```bash
conda create -n rag python=3.11 -y
conda activate rag
pip install -r requirements.txt
```

`.env` 파일에 키와 이메일을 넣습니다. 이메일은 PubMed Central API 이용 규칙에 따라 요청에 함께 보냅니다.

```
OPENAI_API_KEY=발급받은_키
NCBI_EMAIL=본인_이메일
KDCA_API_KEY=질병관리청_발급_키
```

```bash
python collect.py --import-dir manual_files/mohw --source-id mohw --source-name "보건복지부 (수동)" --license "공공누리 확인 필요"   # 수동 파일 등록 (폴더별 명령은 docs/collect_guide.md)
python collect.py --dry-run                                                 # 수집 대상 미리보기
python collect.py                                                           # 문서 수집 + 검사 + 데이터코드 표 작성
python blank_test.py                                                        # 빈손 테스트 실행
python chunk.py                                                             # 정제·청킹 (data/chunks/)
python index.py                                                             # 임베딩 인덱스 (index/, 임베딩은 캐시되어 재실행 비용 없음)
python eval_retrieval.py                                                    # 검색 적중률 (전략 비교)
python eval_retrieval.py --questions eval/questions_v2_draft.csv --only section_ctx --k 10 --per-doc 2 --public 5 --translate
python rag_test.py --questions eval/questions_v2_draft.csv                  # RAG 답변 생성 (기본: 번역 검색 + 공공 5개 + 한 문서당 2개)
streamlit run app.py                                                        # 테스트 화면 (브라우저에서 질문하고 평가 저장)
```
