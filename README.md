# 만성질환 회원 운동지도 보조 AI (가칭)

당뇨·비만·고혈압이 있는 회원을 지도하는 트레이너를 위한 RAG 기반 QA 도구입니다. 회원의 **질환과 그 유형, 연령, 성별, 운동 경력**이 조합된 구체적인 상황을 물으면, 그 조합에서 **무엇을 주의해야 하는지**를 논문·학술지를 근거로 판단해 줍니다. 근거 문서와 쪽(또는 섹션)을 함께 보여주고, 진단·약 조절처럼 의료행위에 해당하는 질문은 의료기관으로 안내합니다.

> 예) "50대 고혈압 판정을 받은 숙련자 남성 회원이 중량을 더 올리고 싶다는데 어떻게 생각해?"
> → 고중량·숨 참기에서 혈압이 어떻게 오르는지, 이 회원 조건에서 증량을 어떤 조건으로 판단할지, 무엇을 먼저 확인할지(혈압 조절 여부, 약, 증상)를 근거와 함께 답합니다.

운동 방법을 처음부터 알려주는 도구가 아니라, 트레이너가 이미 하고 있거나 하려는 지도를 **이 회원에게 해도 되는지, 무엇을 조심해야 하는지** 확인하는 도구입니다. 모델을 다시 학습시키지 않고, 질문마다 모아 둔 문서에서 관련 부분을 찾아 그 근거로만 답하게 합니다.

이 프로젝트의 목표는 챗봇 자체가 아니라 **만들고 → 틀린 것을 찾고 → 고쳐서 → 수치로 증명하는 과정**입니다.

> 이 도구는 운동지도 보조용이며 의료 조언을 제공하지 않습니다.

## 해결하려는 문제

- 같은 고혈압이라도 50대 숙련자 남성의 증량과 70대 초보 여성의 근력운동은 주의할 점이 다릅니다. 지침은 질환별로 나뉘어 있어서, 연령·성별·질환 유형·경력이 겹친 회원 앞에서 어느 기준을 어떻게 적용할지 판단하기 어렵습니다.
- 회원은 "중량 더 올리고 싶어요", "아침 안 먹고 왔어요"처럼 상황으로 말하는데, 지침은 수치와 조건으로 적혀 있습니다.
- 범용 챗봇은 근거 위치를 주지 않고, 진단·약물 이야기까지 해서 비의료기관이 그대로 쓰기 어렵습니다.

## 범위

- **질환:** 당뇨(1형·2형·임신당뇨), 비만, 고혈압(원발성·이차성·임신 고혈압)
- **조합 조건:** 연령(성인·노인·청소년), 성별(남성·여성, 폐경 포함), 질환 유형, 운동 경력(초보·숙련), 임신
- **답변 구성:** 첫 문단에서 트레이너에게 말하듯 결론("진행해도 되지만 ~을 유의해서 지도해야 합니다", 빠진 조건은 되묻기) → **지도할 때 유의할 점**(이 조합이라 다르게 지도할 것) → **회원에게서 지켜볼 점**(임상 대상이라 겉모습·말·행동에서 볼 신호: 신호 → 의심되는 문제 → 왜 → 대처) → **근거**
- **근거 우선순위:** 학술(논문·학회지)을 먼저, 공공(보건복지부·질병관리청 등) 자료는 한국 기준 수치 보충
- **사용자:** 헬스장·PT 트레이너, 생활체육지도자
- **하지 않는 것:** 진단, 약 조절 조언, 범위 밖 질환(근골격계 질환·암·심장·폐·신장 질환 등)과 질환 없는 일반 운동 질문
- **범위 판정:** 답하기 전에 질문을 범위 안 / 일부만 범위 안 / 범위 밖으로 판정합니다(`rag_test.py`의 `check_scope`).
  범위 밖이면 검색·답변 없이 안내만 합니다. 일부만 범위 안이면(예: 비만 + 무릎 관절염) 범위 밖 질환을 뺀 질문으로 답하고, 범위 밖 안내 한 줄을 코드가 붙입니다.
  답변 모델이 범위 밖 질환을 아예 보지 않게 해서, 수집 자료에 있는 관절염·스포츠 손상 내용이 조언에 섞이지 않도록 했습니다.
  판정기가 '범위 안'이라 해도 질문에 범위 밖 질환명(신장 질환·관절염·디스크 등)이 있으면 '일부만 범위 안'으로 바꿉니다.
- **가드:** 진단 요청("무슨 병인지 진단해 주세요")이면 회원을 판정하지 말고 일반 기준과 의료기관 안내만 하도록 규칙을 더하고, 답변에 판정 문장이 남으면 한 번 다시 쓰게 합니다. 의료진에게 넘기지 않고 약·인슐린 조절을 권하는 문장이 있으면(정규식 후보 → 판정기 확인) 역시 다시 쓰게 합니다.

## 평가

평가셋은 `eval/questions.csv` 35문항입니다. 모든 문항은 "50대 고혈압 숙련자 남성 회원이 데드리프트 중량을 더 올리고 싶대요. 어떻게 생각해?"처럼 회원 조건과 상황을 주고 판단을 묻는 형태이고, 채점 포인트 맨 앞에 기대하는 판단을 적었습니다. 질환(1형·2형·임신당뇨, 비만, 원발성·이차성·임신 고혈압) × 대상(성인 남녀·노인·청소년·임신) × 유형(계획 판단 / 운동 시 문제 / 운동 반응 기전)으로 26문항을 짰고, 조건 누락 2문항, 경계 2문항, 범위 확인 5문항(범위 밖 3, 일부만 범위 안 2)을 더했습니다.

- `근거위치` 칸: 검색 평가(`eval_retrieval.py`)용 정답 위치. `문서ID:인쇄쪽` 또는 쪽이 없는 문서는 `문서ID`만 적습니다 (예: `pmc-htn-ex-007; kdca-016`).
- `채점포인트` 칸: 답에 들어가야 할 내용을 ` / `로 나눠 문항당 3~6개 적었습니다. 모두 기대 근거 문서에 실제로 적힌 내용에서 뽑았고, `근거` 칸에 문서ID와 섹션(또는 인쇄 쪽)을 적었습니다. 약 조절처럼 문서에 수치가 있어도 경계에 해당하는 내용은 "의료진과 상의로 안내"를 채점 포인트로 삼았고, 문서에 없는 기준(예: 신장 질환 동반 고혈압의 운동 기준)은 "찾지 못했다고 밝힘"을 채점 포인트로 넣었습니다.
- 임상 내용이라 답변 채점은 자동으로 하지 않고 사람이 합니다. 테스트 화면(`app.py`)의 평가 저장 기능을 씁니다. 자동으로 보는 것은 검색 적중률과 형식 점검(칸, 인용 번호)뿐입니다.
- 채점 포인트와 근거위치는 **초안**입니다. 논문을 고른 사람이 직접 달아서 검색·채점에 유리하게 나올 수 있으니, 사람 검토 후 확정합니다.
- 2026-10-01: 1차 평가셋(13문항)은 질문 수준이 고르지 않고 채점 기준이 질문과 맞지 않는 문항이 섞여 있어 폐기했습니다. 1차 기준 결과(빈손 테스트 채점, 청킹 비교)도 함께 지웠고, git 기록에는 남아 있습니다.

| 지표 | 뜻 |
| --- | --- |
| 검색 적중률 | 기대 근거 문서(또는 쪽)가 검색 결과 안에 드는 비율 |
| 채점 포인트 충족률 | 답에 꼭 들어가야 할 내용 중 들어간 비율 (사람이 채점) |
| 근거 표시 정확도 | 인용한 문서·쪽이 실제 내용과 일치하는 비율 |
| 조건 확인 | 빠진 조건(질환 유형·약·식사·컨디션 등)을 되묻는 비율 |
| 경계 준수 | 진단·약 조절 질문을 의료기관으로 안내한 비율 |

## 파싱·청킹과 검색

`chunk.py`가 사용 문서 93개를 정제해 세 가지 방식으로 자르고, `index.py`가 OpenAI `text-embedding-3-small`로 임베딩합니다. 청크가 수천 개 규모라 벡터 DB 없이 numpy로 전체 코사인 유사도를 계산합니다.

- 정제: 쪽마다 반복되는 머리말·꼬리말 제거, PDF 줄바꿈 복원(한글 단어 중간 끊김은 붙이고 표 칸은 띄움), 인쇄 쪽 번호 자동 인식(PDF 순서와 다른 문서가 있음: 2025 신체활동 안내서 20번째 쪽 = 16쪽), PMC 논문의 부속 섹션과 범위 밖 장(약물치료·입원 등) 제외
- 청크마다 실제로 텍스트가 들어간 쪽 목록과 꼬리표(학술/공공, 질환, 대상)를 기록합니다

| 전략 | 방식 | 청크 수 | 평균 글자 |
| --- | --- | --- | --- |
| fixed | 쪽 안에서 500자씩, 100자 겹침 | 9,661 | 406 |
| fixed_ctx | fixed + 청크 앞에 `[문서명 \| 쪽]` 머리말 | 9,661 | 511 |
| section_ctx | 제목·문단 경계로 나눠 900자까지 묶기 + 머리말 | 5,409 | 706 |

### 검색 방식

질문은 한국어인데 학술 근거는 대부분 영어라서, 한국어 질문으로는 한국어 공공 자료만 올라오고 운동 생리 논문은 거의 검색되지 않았습니다. 그래서 검색 방식을 바꿨습니다.

- **영어 번역 검색:** 질문을 영어로 번역(gpt-4o-mini)해 함께 검색하고, 두 점수 중 높은 쪽을 씁니다.
- **공공 자료 최소 개수:** 번역 검색만 쓰면 영어 논문만 올라와서 한국 기준 수치가 빠집니다. 상위 10개 중 5개 이상은 한국어 질문 점수로 고른 공공 자료로 채웁니다.
- **한 문서당 최대 2개:** 같은 문서·섹션의 비슷한 청크가 상위를 독점하지 않게 합니다.

검색 평가 (`eval_retrieval.py`, 2026-10-02 현재 평가셋으로 다시 잼). 평가셋 35문항 중 기대 근거 문서가 있는 30문항이 기준입니다(범위 확인 5문항은 기대 문서가 없어 제외). 숫자는 기대 문서 적중 수입니다.

| 검색 설정 | fixed | fixed_ctx | section_ctx | 상위 결과 중 학술 수 (fixed) |
| --- | --- | --- | --- | --- |
| 한국어 질문만, 상위 5 | 11 (37%) | 9 (30%) | 7 (23%) | 0.4 / 5 |
| 한국어 질문만, 상위 8 | 12 (40%) | 9 (30%) | 8 (27%) | 0.6 / 8 |
| + 한 문서당 2개 | 13 (43%) | 14 (47%) | 13 (43%) | 0.7 / 8 |
| + 영어 번역 검색 | 28 (93%) | 25 (83%) | 27 (90%) | 7.8 / 8 |
| + 번역 + 공공 5개 이상, 상위 10 (**현재 기본값**) | 27 (90%) | 27 (90%) | 28 (93%) | 5.0 / 10 |

- 현재 기본값(fixed)이 놓친 문항은 8·12·20번입니다(section_ctx는 6·8번). 질문에 위험·기전 이름이 없는 경우입니다: "심박수가 안 오름" → 자율신경병증, "식욕만 늘어" → 운동과 식욕 조절, "부하검사에서 혈압이 과하게 오름" → 운동 고혈압 반응 논문. 상황에서 생길 수 있는 위험을 검색어에 넣어 넓히는 것이 다음 개선 실험 후보입니다.
- 검색 방식(번역·공공 최소 개수)의 효과는 크지만, 청킹 방식 사이의 차이는 1문항이라 우열을 가릴 수 없습니다. 정답이 문서 단위라 청킹 차이를 구분하기에 거칩니다. 쪽·섹션 단위 정답을 확정한 뒤 다시 비교합니다. 답변을 읽어 보니 `fixed`가 주의사항을 더 꼼꼼하게(놓칠 수 있는 부분까지) 담아서, 주의사항을 우선해 기본값을 `fixed`로 둡니다(2026-10-02).
- 오답노트 후보: 고중량 운동 질문(17번)에서 발살바 압력 논문을 못 찾음, 운동 후 어지럼 질문(18번)에서 운동 후 저혈압 기전 논문을 못 찾음, 기전 질문에도 답변 형식 때문에 권장 운동 칸이 채워짐, 같은 안내서의 연도판(2024·2025·2026)이 상위를 나눠 차지함.
- 데이터 한계: 신체활동 지침서는 홀수 쪽이 모두 0자로 추출됩니다(당뇨·고혈압 운동 기준이 있는 49쪽 포함). 그림으로 들어간 글자라 OCR이 필요합니다 → 첫 개선 실험 후보.

## 테스트 화면 (Streamlit)

`streamlit run app.py`를 실행하면 브라우저에서 답변을 확인할 수 있습니다.

- 질문을 직접 쓰거나 평가셋 문항을 고릅니다. 문항을 고르면 채점 포인트와 기대 근거 문서가 함께 보입니다.
- 왼쪽에 답변, 오른쪽에 검색된 근거(학술/공공, 점수, 인용 여부, 기대 문서 여부)가 나옵니다.
- 자동 점검: 형식 3칸(지도할 때 유의할 점·회원에게서 지켜볼 점·근거)이 있는지, 인용 번호가 실제 검색 결과에 있는지, 학술 근거를 몇 개 인용했는지, 기대 문서가 검색됐는지.
- 사람 평가: 항목별 좋음/부족/틀림과 메모를 저장하면 `logs/qa_log.sqlite`에 쌓이고, 화면 아래에서 CSV로 받을 수 있습니다.
- 사이드바에서 청킹 방식, 근거 수, 공공 자료 최소 개수, 문서당 최대 개수, 영어 번역 검색을 바꿔 가며 비교할 수 있습니다.
